## Updater and pinned trust

`launcher-update-service.ts` extends the existing update boundary with idle/checking/available/downloading/downloaded/installing/up-to-date/deferred/error/unsupported. The NSIS adapter uses installed electron-updater6.8.9/electron-builder26.15.3 without major migration, custom updater executables or self-replacing code. Auto-download and auto-install-on-quit are false. Startup checks once after UI loads; manual checks throttle30s. Only explicit user download/install operations run. Installed/signed NSIS marker, trusted publisher and no running Skyrim/SKSE are required for self-install; game/Steam/server are never terminated. Errors are redacted, subscriptions disposed, concurrent requests refused and interrupted/retry/install-error states handled. Settings remain in the original user-data location. New installed version is only evidenced by the next process reporting it.

Publisher pins in `update-bootstrap.ts` are deliberately empty: **BLOCKED BY SIGNING**. Missing publisher metadata blocks download/install rather than letting v6 bypass signature checks. With verified pins configured, the default library Authenticode verifier is retained and an extra exact Valid/subject check fails closed (including legacy PowerShell fallback). Checksums are integrity only; v26 latest.yml is not assumed Ed25519-signed. Trust is public HTTPS GitHub owner/repo plus pinned Authenticode signer for executable acceptance. v27 signed-update-manifest migration, manifest signing keys/rotation and approved publisher certificate rotation need separate investigation/authorization; never set verification false/null. Public provider is explicitly github/kaktv2016/frostveil-launcher/private:false, not inferred from origin. End users need neither Git nor GitHub tokens.

Stable-only: allowPrerelease=false, channel latest, allowDowngrade=false **after** setting channel (v6 channel setter otherwise enables downgrade). Beta controls are disabled until cross-channel isolation is demonstrated. Old beta preferences may remain stored but never enable beta downloads. Modpack contracts remain L1 read-only fixtures; no mod Install/Repair/apply feature in L2.

Cached installers are independently SHA512/signature rechecked after the library download returns and again just before NSIS installation. This closes the v6 same-process cached-path existence shortcut; no cached file is accepted merely because it exists. Asynchronous NSIS error events restore a retryable downloaded state without leaking raw installer paths.


Package commands always use `--publish never`; generated unsigned local installer is not a production update. app-update.yml must match explicit provider and latest.yml must match package.version/installer. Tests use mocks for checks/progress/defer/install plus the pinned library DigestTransform against valid/tampered bytes. Fixture smoke observes updater UI and blocks real self-install/Skyrim launch. These tests do not prove installed0.1.0→0.1.1 migration.

## CI and publication

Windows workflow runs npm ci/typecheck/tests/build/NSIS metadata verification/development and packaged fixture smoke. Safe unsigned development installers/metadata may be uploaded as Actions artifacts, explicitly labelled development-only. Public executable Releases are a different gate.

Release workflow has workflow_dispatch only, explicit approval input and `production-release` environment requiring owner review. No branch-push publication or automatic tag creation. It requires a separately approved existing `v<package.version>` tag, certificate secrets, exact reviewed public signer pin, signed nonpublishing package and valid matching signer on both EXE and installer before any explicit gh release command. Uses scoped GITHUB_TOKEN and contents:write only on the gated job. Never dispatch this workflow without separate public executable approval.

Missing: reviewed trusted signer subject, WINDOWS_CERTIFICATE/WINDOWS_CERTIFICATE_PASSWORD secrets and WINDOWS_PUBLISHER_SUBJECT variable. Certificate/private key must never enter source/logs. Production and real installed update acceptance remain blocked until configured and separately approved. L1 unsigned installer has no configured provider/publisher and is not retroactively self-updatable; manual approved migration is necessary before production automatic updates.

## Remaining acceptance
