# Frostveil L3 Implementation Plan

> Execute inline with executing-plans and TDD. The user's supplied L3 specification authorizes implementation and all local verification; no additional approval handoffs, commits, pushes or releases.

**Goal:** Read-only modpack verification against an authenticated or explicitly local development profile, without replacing SkyMP's loader or changing game/server/world data.

**Architecture:** Extend the existing PackManifest V1 contracts, retain L1 field names, discovery, baseline and safe filesystem helpers. Separate schema/trust, offline server export, scoped scanner, plugin evidence, evaluator/planner and main-process orchestration. Integrate one typed IPC event and Updates panel. Local development evidence is labelled offline, never live or production-authenticated.

**Tech:** Existing TypeScript/React/Electron, Node crypto Ed25519 and streamed SHA256, existing semver. No new dependencies.

**Spec:** User's supplied “Frostveil Launcher — L3: Modpack Manager & Server Compatibility Verification”.

## Constraints and rulings

- Zero writes to game, SKSE/client, server configuration/source, load order or world. No game launch in automated checks.
- Preserve app/installer/user-data identities, L1 gate and L2 signer protection. Mandatory modpack enforcement defaults off and is main-process controlled.
- Do not authenticate the private 24-file L1 baseline as a server release. Explicit client requirements are locally authored development configuration.
- Pinned SkyMP 2849e676 engine / 5397cd3 working checkout: manifestGen .esm/.esp only; native Combiner maps full plugin indices. Required light plugins produce UNVERIFIED, not fabricated support.
- Profile export accepts known local settings + existing plugin manifest, reads plugin headers/hashes, exports a whitelist only. Remote/additional configuration needs an explicitly resolved snapshot; no setup/server execution.
- No production trust key/source configured; signed synthetic tests are test-only. No real remote asset requests.
- Config-derived plugin evidence is separate from live load order. Ambiguous/managed views fail closed. Required shared plugins use SkyMP full-index prefix semantics, client-only assets do not require server presence.
- Existing unconfigured L1 manifests are replaced by the extended strict contract; retain existing field names and files array, no parallel incompatible modpack schema.

## Review focus

1. Stale/foreign server snapshots and pinned pack bindings must never turn green.
2. Scan cancellation must work during IPC busy lock, clear old success and prevent stale selected-directory results.
3. Hash mismatch is modified unless verified version evidence says outdated; access denial is scan-error.
4. Safe relative paths, case collisions, link escapes and bounded metadata/file reads.
5. Unknown order, header parse failures, light plugins and virtualized views must not fabricate effective runtime evidence.
